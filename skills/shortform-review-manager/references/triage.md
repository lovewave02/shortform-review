# 검토 기록

영상별 비공개 상위 폴더에 `triage.md`를 두고, 그 아래 새 실행별 폴더에 보고서를 둔다. 예: `.local-runs/video-a/triage.md`, `.local-runs/video-a/run-001/report.json`. 자동 보고서는 원본 그대로 보존한다. 기존 기록이 있으면 보고서 경로와 해시를 명시하여 검토 이력을 덧붙인다. 이미 다른 위치의 보고서가 있으면 옮기지 않고 원래 경로·해시로 연결해도 된다.

```markdown
# 검토: <영상 식별명>
- report: <로컬 report.json 경로>
- source SHA-256: <보고서 값>
- tool version / settings: <보고서 값>
- observed checks / skipped / errors: <실행 범위>

| finding / rule / time | 판정 | 확인 근거 | 다음 행동 |
|---|---|---|---|
| <현재 보고서의 finding 식별자 또는 순번·규칙·시간> | 추가 확인 | 아직 재생 확인 전 | 해당 구간 확인 |

## 재검사
- 새 report / source SHA-256:
- 비교 가능성: 같은 검사·설정인지, 자막/시간 이동 여부
- 해결 / 신규 / 재발 / 비교불가:
- 테스트와 코드 변경:
```

finding 순번은 보고서 안에서만 유효하다. 다른 파일이나 재검사 결과에 같은 순번을 자동 대응시키지 않는다. 고정된 조건에서 확인한 오탐은 이유를 기록하되 원본 검사 결과에서 제거하지 않는다.

도구 결함에는 최소 재현 입력, 기대/실제 결과, 실행 버전과 설정을 남긴다. 실제 제작 파일은 로컬에 두고 공개 테스트는 합성 데이터로 작성한다. 수정된 영상의 새 검사와 사람 확인이 없으면 `해결`로 쓰지 않는다.
